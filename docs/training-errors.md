# Две ошибки для самостоятельного исправления

17 октября 2026 обе ошибки воспроизведены на работающем приложении и приняты collector. Это реальные дефекты существующего кода — дополнительных поломок в исходники не внесено, исправления не запускались.

После согласования runtime-базы актуальны **INC-126** и **INC-127** (source revision `367c7e14…`). Прежние INC-119/120/125 и job-71 относятся к старой версии; не продолжайте их для деплоя на новую базу.

## 1. Каталог: некорректный номер страницы — INC-126

Открыть **http://127.0.0.1:8085/market?page=training-page**.

Сейчас: HTTP 500, `java.lang.NumberFormatException` в `MarketService.marketMainService`.

Цель для агента:

> Исправь обработку параметров пагинации каталога: нечисловой page не должен приводить к HTTP 500. Возвращай понятный HTTP 400 либо безопасно используй первую страницу. Сохрани работу корректной пагинации и добавь regression tests. Не скрывай исключение только в логах.

## 2. Оформление заказа без входа — INC-127

В приватном окне браузера, без входа в **aurelSpa**, открыть **http://127.0.0.1:8085/cart/order**. Вход в AI Doctor — отдельная сессия и на этот сценарий не влияет.

Сейчас: HTTP 500, `java.lang.NullPointerException` в `CartService.cartOrder`: `user` равен `null`.

Цель для агента:

> Исправь открытие оформления заказа неавторизованным пользователем: направляй его на страницу входа либо возвращай корректный отказ, без HTTP 500 и NullPointerException. Сохрани оформление для авторизованного пользователя, не ослабляй CSRF или контроль доступа. Добавь regression tests для гостя и вошедшего пользователя.

## Повтор и проверка

Из каталога `ai-doctor`, без сторонних Python-зависимостей:

```bash
python3 scripts/reproduce_training_errors.py
# Отдельно:
python3 scripts/reproduce_training_errors.py --case page
python3 scripts/reproduce_training_errors.py --case checkout
# После исправления и развёртывания:
python3 scripts/reproduce_training_errors.py --expect-fixed
```

Скрипт делает только GET-запросы на локальный стенд, не отправляет заказ, не создаёт учётную запись и не следует редиректам. Сейчас оба сценария возвращают 500; повтор увеличивает счётчики тех же инцидентов. После изменения версии приложения номера новых инцидентов могут отличаться. Проверка ответов не заменяет regression tests и проверку доступа для вошедшего пользователя.

В AI Doctor открыть соответствующий инцидент → «Подготовить исправление» → вставить цель. Не исправлять обе проблемы одной задачей, если хочется пройти два отдельных цикла.

**Блокировка стенда устранена:** исходники и runtime согласованы с полным сравнением JAR и архивом старого журнала. Проверки доверия не отключались. Подробности: [baseline-reconciliation.md](baseline-reconciliation.md). В браузере проверены обе свежие карточки и доступность кнопки «Подготовить исправление»; сами Fix Agent задачи при проверке кнопок не запускались.
